**Overrides editoriais (enriquecimento manual):** o merge faz TRUNCATE e reconstrói do CNES/Receita, apagando edições manuais (site, descrição, contato). Tabela **`clinic_overrides`** (cnpj PK, website, description, full_description, phone, whatsapp, email, address, neighborhood, cep) guarda o enriquecimento; o `30-merge.mjs` **reaplica por CNPJ após o insert** (coalesce, só sobrescreve o que o override tem). **Reportar erro na ficha (corrections):** cada página de clínica (`[slug]/[clinicSlug]`) tem o botão "Informar erro ou dados desatualizados" (`report-error-button.tsx`) → POST `/api/public/corrections` → salva em `clinic_corrections` (status pending) + `notifyCorrection` e-mail p/ ADMIN_EMAIL. Tipos: closed ("não existe/fechou"), phone, whatsapp, address, name, other. Sem painel admin (removido no v1); acompanhar por e-mail ou consultando a tabela.

**Remoção por notificação legal (LGPD/LPI):** o merge faz `TRUNCATE clinics CASCADE` e reconstrói do CNES a cada ingestão, então só deletar o registro NÃO basta (volta na próxima ingestão). Existe tabela **`clinic_blocklist`** (cnpj, cnes, name, reason) que o `scripts/ingest/30-merge.mjs` lê e pula (skip por CNPJ ou CNES no início do loop). Para atender takedown: (1) INSERT na `clinic_blocklist`; (2) DELETE do registro em `clinics` (filhos caem em cascade, `clicks` vira set null); (3) rebuild (`rm -rf .next && npm run build`) p/ tirar do sitemap + pm2 reload casasrec/casasrec-b; (4) Cloudflare purge + IndexNow da URL removida (vira 404). 1º caso: Espaço Terapêutico Renovação, CNPJ 51.490.807/0001-90, CNES 4290488 (notificação 18/08/2026).
