Sistema novo (criado 2026-06-05) para portais de notícias **sem WordPress**: HTML estático puro, recebe artigos do **Sistema Antônio** e publica automático. Objetivo: fugir do peso do WP e replicar portais rápido.

**Relação de portais + regra:** `D:\SISTEMAS\portal-engine\SITES.md` = lista oficial (domínio, arquétipo, endpoint, X-API-KEY, status), sincronizada com sites.json. **REGRA (no CLAUDE.md): ao criar/alterar portal, SEMPRE atualizar SITES.md + sites.json local (sync da VPS) + seção Status.** O `sites.json` local foi sincronizado com a VPS (fonte da verdade = `/opt/portal-engine/sites.json`). Dados dos sites (artigos+HTML) só na VPS em `/srv/portais/<slug>/`, nunca local. 3 portais no ar: romanceseleituras (A), projetob/"Projeto B News" (B, endpoint www), todossomosgeek/"Todos Somos Geek" (C).

**Código (superfície VS Code/Git):** `D:\SISTEMAS\portal-engine\` — sites.json, src/render.js (motor de render + slugify + SEO/schema), src/receiver.js (HTTP Node puro, zero deps), newsite.sh (provisiona portal), portal-engine.service.

**VPS:** `hostinger-vps-srv1166087` (31.97.173.40, Ubuntu 24.04, HestiaCP gerenciando Nginx+Apache, Cloudflare na frente). **BLINDAGEM:** roda como usuário `portais` (sem sudo) via **systemd** `portal-engine` (NÃO o PM2 dos bots — não tocar nos bot-sae/bot-afiliado), MemoryMax 512M, sandbox, escuta só 127.0.0.1:8791. Conteúdo em `/srv/portais/<slug>/{data,public}`, código em `/opt/portal-engine`. Certs em `/etc/ssl/portais/<dominio>/`.

**Fluxo:** Antônio faz POST `X-API-KEY` (mesmo formato dos WP, ver [[reference_antonio_endpoint_recovery]]) → Nginx (location `~ /[a-z0-9_-]+/v1/artigos$`, aceita custom E `/wp-json/...`) → receptor Node identifica o site pela API key → render.js gera HTML + sitemap/robots, salva data JSON pra rebuild. Receptor recarrega sites.json sozinho (fs.watch, sem restart). Design editorial parametrizável por site (cor+fontes em sites.json) p/ anti-fingerprint.

**Replicar:** `bash /opt/portal-engine/newsite.sh <slug> <dominio> "<Nome>"` (cria pastas, gera API key, vhost com guarda `nginx -t`). Depois: DNS A no Cloudflare (laranja) → IP, SSL Full, e cadastrar endpoint+key no Antônio.

**Detalhes importantes do receptor:** (1) O Antônio envia `content` com HTML **entidades-codificado** (`&lt;p&gt;`); o motor faz `decodeEntities()` (equivalente ao `html_entity_decode` do WP) senão o conteúdo aparece como código. (2) Categoria/autor vêm como ID numérico WP → mapeados via `categoryMap` no sites.json (ID→nome) + `defaultCategory` (fallback). romanceseleituras: **1=Notícias, 2=Entretenimento** (defaultCategory=Notícias); autor numérico→nome do site. Pra adicionar categoria: incluir o ID no categoryMap e usar esse ID no campo "ID Categoria WP" do Antônio. (10) **catLock**: pra mover um artigo de categoria de forma durável (o Antônio re-entrega e desfaz), setar `catLock:true`+`category` no data JSON; publishArticle preserva categoria travada nas re-entregas. (11) **IndexNow** ativo: cada site tem `indexnowKey` no config + arquivo `/<key>.txt` servido; publishArticle pinga api.indexnow.org automaticamente (Bing/Yandex/Seznam; Google é via sitemap/GSC). (12) **Escrita ATÔMICA obrigatória** (writeAtomic: temp+rename) em tudo que o nginx serve — o Antônio re-entrega o MESMO artigo ~1x/min, disparando rebuilds; sem atomic o nginx lia arquivo no meio da reescrita → 502. (13) Antônio re-entrega o mesmo conteúdo repetidamente (possível má config da campanha) — sistema é idempotente, aguenta. (3) Imagens são otimizadas no save via ImageMagick (`convert -resize '1000x>' -strip -quality 82`) + `identify` captura w/h reais (evita CLS; Antônio manda 16:9). (4) Fontes Google carregadas non-blocking (preload+media=print onload). (5) NUNCA rodar rebuild como root (cria arquivos root → EACCES no receptor portais); usar `runuser -u portais -- node`. (6) Conteúdo do Antônio vem com **backlinks externos injetados** (ex: IPTV) — é a monetização da rede; não remover sem pedido. (7) Cache Cloudflare: ao re-otimizar imagem com mesmo nome, o CF serve a antiga (vhost expires 30d). Solução SEM purge: cache-bust na URL da imagem `?v=WxH` (dimensões) — o motor já faz isso; muda o v quando a imagem muda. (8) CRÍTICO: **SEMPRE `systemctl restart portal-engine` após editar render.js** — o `require` do Node cacheia o módulo; sem restart o receptor roda código ANTIGO (causou conteúdo encodado persistente mesmo após deploy+migração, pois cada retry do Antônio re-quebrava com o código velho). (9) Conteúdo do Antônio é DUPLO-encodado (`&amp;lt;`) — decodeEntities roda em loop (até estabilizar). A linha fina (dek/standfirst) vem como `<i>` no início do conteúdo; o motor extrai e posiciona abaixo do título.

**Anti-fingerprint — ARQUÉTIPOS estruturais (2026-06-05/06):** além de tema (cor+fontes), o motor tem **3 arquétipos de DOM/classes** via `site.layout.arch`: **'A' (editorial clássico)** = topbar + masthead central + nav.cats + lead/grid/card + single `.article`/`.body` (drop-cap) + footer `.site .cols`; **'B' (magazine)** = header split `.hd`/`.hd-nav` + `.fhero`+`.fcols`(`.fmain` feed `.fitem` + `.fside`) + single `.post-head`/`.post-hero`/`.prose` + footer `.ft`; **'C' (portal de NOTÍCIAS / cyber newsroom)** = `.tg-ticker` (AO VIVO pulsante) + `.tg-brand` + `.tg-nav` + home `.tg-hero` (lede `.tg-lede` + rail numerado `.tg-rail`) + **blocos por editoria** `.tg-sec`/`.tg-grid`/`.tg-card` + single 2-col `.tg-art`(`.tg-story`+`.tg-aside` relacionadas)/`.tg-body` + footer `.tg-foot`. Dispatch 3-vias via `arch(site)`/`archB`/`archC` em render.js (header/footer/homePage/articleHtml/listPage). `cssB()`/`cssC()` só injetados no arquétipo certo (zero regressão). A **ordem do `<head>`** também tem 3 variantes (A/B/C). Pra adicionar arch D: criar funções variante + `cssD()` + estender dispatch + ordem head + preset. Overlap de classes entre os 3 ≈ só `wrap`/`sr-only`/`kicker` (genéricas). **A ordem do boilerplate do `<head>`** (blocos title/SEO/OG/Twitter/ícones/fontes + ordem interna dos campos OG/Twitter/ícones) também **diverge por arquétipo** em `head()` — evita HTML byte-idêntico entre portais (resíduo de fingerprint fechado 2026-06-06). Overlap de classes CSS medido entre A e B = ~9,5% (só genéricas wrap/kicker/reveal/sr-only). Sem pegada WP (wp-json 404, sem generator). Resultado: portais divergem em **DOM + nomes de classe + paleta + fontes** (não só cor). Para adicionar arch C/D: criar as funções `*ClassicX` + cssX e estender o dispatch.
