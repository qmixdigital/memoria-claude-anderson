O `header.php` gerado pela skill wp-news-frontpage (ao menos archetype H3 "Centered split", visto em revistarumo.com.br) coloca `display:none` nos menus desktop (`.rr-site-header__menu-left/right`) no breakpoint mobile, mas NÃO gera nenhum botão hambúrguer nem drawer off-canvas. Resultado: em telas ≤1100px o portal fica sem navegação de editorias — só sobra o ícone de busca. O CSS de `menu-toggle`/`mobile-drawer` que aparece no HTML ao vivo é inline ÓRFÃO do Kadence (tema pai gera sempre, mas o elemento não existe porque o child-theme substitui o header inteiro).

**Why:** quebra grave de UX/SEO mobile — maioria do tráfego é mobile e o usuário não consegue navegar entre categorias.

**Variante df8 (archetype prefixo d8-, corrigido 2026-06-17):** pior — o `refine.css` E o `chrome.js` do fix mobile targetam classes `.d8-nav`/`.d8-nav__list`, MAS o header renderiza `.d8-navbar`/`.d8-navbar__menu`. Dois bugs: (1) menu desktop nunca escondido no mobile (CSS miss), (2) painel do hambúrguer nunca montado — JS `sourceMenu` não achava o menu → burger abria vazio. Fix: append em refine.css `@media(max-width:1024px){.d8-navbar{display:none!important} .d8-masthead__burger,.d8-menu-toggle{display:inline-flex!important} .d8-mobile-panel{display:block!important}}` + adicionar `.d8-navbar__menu` no `document.querySelector` do chrome.js. Backups `.bak-20260617` na hostverge (`/home/sites/18a/7/7672b9147f//public_html/df8.com.br/wp-content/themes/portal-df8-com-br/`). **CAVEAT hostverge: LiteSpeed CSS/JS combine ON** — após editar assets do tema, purgar (`wp eval do_action("litespeed_purge_all")` + `rm -rf wp-content/litespeed/*`) senão o bundle combinado serve a versão antiga. Lição: ao auditar header de portal, conferir as classes REAIS do header (.d8-nav vs .d8-navbar) contra o que o fix CSS/JS targeta.

**Variante desassossegada (archetype prefixo dsg-, corrigido 2026-06-17):** SEM nenhum burger/drawer/JS (tema nem tinha arquivo JS). Pior: o `dsg-nav` saía VAZIO em desktop E mobile porque (a) `primary` não tinha menu atribuído (`nav_menu_locations` vazio) e (b) o fallback `dsg_default_menu_fallback` era definido DEPOIS da chamada `wp_nav_menu` no header.php → fallback não existia na hora → nav vazio. Fix: (1) mover a def do fallback pro TOPO do header.php (antes do nav); (2) add burger em `dsg-header__bar-left` (esquerda, oposto à lupa em bar-right) + `.dsg-mobile-panel` off-canvas (renderiza o menu server-side via wp_nav_menu, não clona) + overlay; (3) CSS append em style.css `@media(max-width:1024px)`: esconde `.dsg-nav`, mostra burger, esconde `.dsg-header__tagline`, mantém `bar-left` visível; (4) JS inline no foot.php (toggle/ESC/backdrop/fecha-no-link). Backups `.bak-20260617` na qmix (`/home/u463007860/domains/desassossegada.com.br/public_html/wp-content/themes/portal-desassossegada-com-br/`). CAVEAT: qmix tb tem LiteSpeed CSS/JS combine → purgar + `rm -rf wp-content/litespeed/*`. JS inline SOBREVIVE (LiteSpeed só minifica o comentário). Grid do header é `1fr auto 1fr` (burger esq / logo centro / lupa dir).

**How to apply:** ao gerar/auditar qualquer portal da rede com essa skill, conferir se há hambúrguer + drawer mobile no header. E conferir se o `wp_nav_menu`/fallback realmente popula (nav vazio = fallback definido tarde ou sem menu em 'primary'). Fix aplicado em revistarumo (2026-06-05): botão `.rr-site-header__burger` (44px, oculto desktop / inline-flex ≤1100px) + `.rr-mobile-nav` off-canvas com backdrop e JS de toggle (Esc/backdrop fecham), touch targets ≥48px. Backups `.bak-20260605` no servidor anderson (`hostinger-anderson-gna`, path /home/u400588174/domains/revistarumo.com.br/public_html). Vale checar os demais archetypes de header da skill. Ver [[reference_litespeed_js_optimization_quebra_gutenberg]] sobre cache LiteSpeed servindo assets antigos.
