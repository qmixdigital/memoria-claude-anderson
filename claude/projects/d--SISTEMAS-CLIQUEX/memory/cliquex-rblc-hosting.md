**rblc.com.br** = site **nº 1 no Google** em "teste iptv" (do usuário). É um app **Next.js (static export)** publicado no **Cloudflare Pages (direct_upload)**, projeto **`rblc`**, na conta **`conta3` do contas.json = TRAFEGOPAGO** (account `0a107ac0726c16a763c318bf7a45b57d`, zona `69ff82aaba73b70d6e463f38e8c7d6d4`). NÃO está na conta 39a13af3 (a dos money sites da série); o master token `cfut_reEz` NÃO enxerga rblc. Usar o token da entrada `conta3` no contas.json. Essa conta é **plano Free**: Snippets/Workers dão **403 "not allowed"** (sem edge-injection possível). Estrutura = mesmo silo (home + ~110 `/teste-iptv-*` + termos + privacidade), sitemap índice (`/sitemap-pages.xml` tem 129 locs, maioria `/?q=...` = home com query). Schema rico do rblc (o modelo que copiei pros money sites): ImageObject + Product+AggregateRating+AggregateOffer + Review + FAQPage + HowTo + CollectionPage — ver [[cliquex-testeiptvwales]].

**REMOÇÃO DO BANNER (2026-08-27):** o rodapé tinha um banner de cross-promo `<div id="pm-banner" role="complementary">` (position:fixed, link `palpitemestre.com.br/palpites?utm_campaign=rodape`, botão fechar `.pmb-x`), embutido no build (aparecia igual no rblc.com.br E rblc.pages.dev; NÃO é edge). Usuário apagou a fonte local e pediu pra tirar. Sem fonte e sem Worker/Snippet, fiz **mirror + strip + redeploy**: `scratchpad/rblc_mirror.py` baixou as 114 páginas do `rblc.pages.dev` + 226 assets, removeu o bloco EXATO do banner (2743 chars, salvo em `rblc_banner_block.txt`, via `.replace` literal + fallback balance-match de `<div>`), e redeployei o build no projeto Pages `rblc`. Verificado: pm-banner=0 no HTML servido, conteúdo+schema (AggregateRating/FAQPage/ImageObject) intactos, tudo 200. Deploy anterior (com banner) fica no histórico do Pages p/ **rollback**.

**MAS o strip do HTML NÃO bastou (o usuário continuava vendo o banner até no celular):** o banner é um **componente React re-injetado pelo JS no cliente** (chunk `_next/static/chunks/0ht-qf6qytxe4.js`, módulo 37800: `function(){let[e,n]=useState(!1);return e?null:jsxs("div",{id:"pm-banner",...})}`). Remover só do HTML não adianta — a hidratação recria o banner no navegador. **FIX REAL (2 camadas, redeploy):** (1) **patch no JS**: `useState(!1)`→`useState(!0)` no componente (inicia "fechado" → sempre retorna null, nunca renderiza); (2) **CSS de trava** `<style>#pm-banner{display:none!important;visibility:hidden!important}</style>` no `<head>` das 114 páginas (esconde mesmo se um navegador tiver o JS antigo em cache). Chunks `/_next/static/` do rblc são `max-age=14400, must-revalidate` (NÃO immutable), e o HTML revalida sempre → o fix chega rápido. **LIÇÃO: banner/widget que reaparece após strip do HTML = injeção client-side (React/JS); tem que patchar o chunk JS E/OU esconder via CSS, não só editar o HTML.** **RESSALVA:** o deploy é um snapshot estático; se rebuildarem do código Next.js original, o banner VOLTA (está no componente de rodapé) — tirar da fonte quando recuperá-la.

**GOTCHA token via bash:** passar o token do contas.json pro wrangler via arquivo/`$(cat)` no bash corrompeu um char (virou em-dash U+2014 → wrangler recusa). FIX: fazer o deploy pelo **Python subprocess** lendo o token direto do JSON (`"".join(ch for ch in tok if ch.isascii())`) e setando `env["CLOUDFLARE_API_TOKEN"]`; o token é ascii de 53 chars e funciona em urllib. (O `capture_output` do subprocess quebra com UnicodeDecodeError cp1252 no output emoji do wrangler, mas `returncode 0` = deploy OK.)
